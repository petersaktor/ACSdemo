# Implementation Plan: ACSdemo Refactoring — Email Notification Controller

**Branch**: `001-email-notification-cosmos` | **Date**: 2026-04-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-email-notification-cosmos/spec.md`

## Summary

Refactor ACSdemo from a flat ACS send/receive service into a
clean-architecture microservice. Remove three legacy controllers
(`EventsController`, `MessagesController`, `WeatherForecastController`) and all
exclusively-owned models/services. Introduce a single
`EmailNotificationController` that subscribes to the Dapr pub/sub topic
`EmailDeliveryReportReceived`, persists the incoming ACS delivery report to Azure
Cosmos DB via a MediatR command, and exposes a HotChocolate 15 GraphQL API for
querying those reports. The project adopts the `Domain / Application /
Infrastructure / Web` logical folder structure mandated by the constitution, with
MediatR 12.x for all business operations and FluentValidation 11.x co-located
with every command and query.

## Technical Context

**Language/Version**: C# 13 / .NET 10.0 (net10.0), ASP.NET Core 10  
**Primary Dependencies**: MediatR 12.x, HotChocolate.AspNetCore 15.x, HotChocolate.ApolloFederation 15.x, FluentValidation 11.x, Microsoft.Azure.Cosmos, Ardalis.GuardClauses, Dapr.AspNetCore 1.x, Azure.Identity  
**Storage**: Azure Cosmos DB (Microsoft.Azure.Cosmos); container `EmailDeliveryReports`, partition key `/recipientAddress`  
**Testing**: N/A — no automated tests (Constitution Principle IV)  
**Target Platform**: Linux container, Azure Container Apps  
**Project Type**: microservice / event-driven web service  
**Performance Goals**: Event ingestion ≤5 s end-to-end (SC-001); GraphQL query ≤1 s (SC-002)  
**Constraints**: Single .csproj (Principle II); secrets in Azure Key Vault via App Configuration (Security); no REST endpoints for business logic (Principle III)  
**Scale/Scope**: Single service; low-to-medium throughput (email delivery reports); no horizontal scale constraints at MVP

## Complexity Tracking

> **Fill ONLY if Constitution Check has violations that must be justified**

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| `IEmailDeliveryReportRepository` interface in `Application/Ports/` | Application layer must not reference Infrastructure (constitution Principle II dependency rule). The handler in `Application/Commands/` needs to call Cosmos DB, which lives in `Infrastructure/`. An interface in `Application/Ports/` is the only way to satisfy this without coupling the layers. | Direct `CosmosClient` injection into the handler would couple Application to Infrastructure, violating the stated dependency rule. |
| Bicep folder rename `deploy/` → `.infrastructure/` | Constitution mandates all IaC under `.infrastructure/`. Git history of Bicep files preserved via rename. | Keeping `deploy/` would leave the codebase in permanent violation of the Constitution Infrastructure principle. |
